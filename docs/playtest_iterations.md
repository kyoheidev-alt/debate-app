# 実プレイ改善ループ

対象: 本番 `https://debate-app-pi.vercel.app/`（2026-09-11）およびローカル `http://localhost:3001`。
このアプリにターン・タイマー・投票・勝敗・再戦はない。授業用の匿名チャットである。

## Iteration 1

### 今回のテスト

トップを初見ユーザーとして開く。UUID 以外を送信。使い方・ログイン・存在しないルームURLを開く。

### 発見した問題

1. トップに目的説明がなく、巨大な UUID 欄だけがある
2. フッターの「使い方」は小さく、初回クリックでは遷移しなかった
3. 「UUID形式」というエラーは中学生に通じない
4. ログイン／新規登録の見出しが扉の上でほぼ読めない（`text-slate-900`）
5. 存在しないルームは英語の 404

### 各レビュアーの評価

初心者: 何をするアプリか分からない。
UX: 視線はロゴ→黄色ボタン。説明は読まれない位置。
ディベート経験者: 議論以前に入れない。
ディベート初心者: 参加ハードルが ID 形式で高い。
コミュニティ: この段階では未評価。
スマホUX: UUID プレースホルダが入力欄を埋め尽くす。
ゲームデザイン: 開始前に離脱する。
QA: 不正入力のフィードバックはあるが用語が専門的。

### 最大の問題

初見が「何をすればいいか」分からない。

### 議論

賛成: 説明を足すべき。
反対: `/guide` の長文は読まれない（実際にトップから辿り着きにくい）。
最終判断: カード内2文＋招待リンク貼付を主経路にする。ガイド全文は増やさない。

### 実施した改善

* トップに目的と「リンクを貼る」案内
* 使い方／議長ログインをカード内へ
* 招待URLからルームIDを抽出
* 見出しをゴールドに
* 日本語 404

### 再テスト

結果: 部分的に解決した。

### 改善前

UUID 手打ちと英語 404。見出しが読めない。

### 改善後

目的文と使い方がカード内にある。不正入力は「リンクを貼って」と案内する。404 は日本語。

### 新しい問題

* ローカルでは Service Role 未設定のため入室ページが落ちる（本番は可）

### 次回確認

* 本番でもリンク貼付で入れるか

## Iteration 2

### 今回のテスト

既存テストルームに `student001` で入室し、反対意見を送信。DB と画面を照合。

### 発見した問題

1. 投稿は DB に保存されたがチャットに出ない（Realtime 任せ、insert 後に state 更新なし）
2. 失敗しても下書きが消える（`onSend` が throw しない）
3. `is_name_visible=false` でもクライアントが `name`/`login_id` を取得している

### 各レビュアーの評価

初心者: 送ったのに消えたと感じる。
UX: フィードバックが「消える」だけ。
ディベート経験者: 相手の意見が見えないと議論が成立しない。
QA: P0。Realtime 切断で再現。
コミュニティ: DevTools で実名が取れる。

### 最大の問題

自分の主張が画面に残らない。

### 議論

賛成: Realtime を直すべき。
反対: Realtime 復旧待ちでは授業が止まる。
最終判断: insert の戻り値をローカル state に足す。Realtime INSERT は id で重複排除。

### 実施した改善

* `select().single()` 後にメッセージを即追加
* 失敗時は throw して下書きを残す
* 実名表示 OFF では `name`/`login_id` を select しない
* 入室画面から UUID と議長実名を外す

### 再テスト

結果: ユニットテストでフィルタを確認。チャットの目視再確認はデプロイ後。

### 改善前

送信 → 入力が空 → 一覧は「あ」「aaa」のまま。

### 改善後

コード上は自分の投稿がすぐ `messages` に入る。

### 新しい問題

* RLS ではまだ生徒が `profiles.name` を直クエリできる

### 次回確認

* 本番デプロイ後に同じ投稿シナリオを再実行

## Iteration 3

### 今回のテスト

チャット空状態・プレースホルダ・本番の短文ログを観察。

### 発見した問題

1. 空状態が「最初の意見を投稿しましょう」だけで手順がない
2. プレースホルダが「反対の立場で発言…」で、何を書けばいいか分からない
3. 本番ログは「あ」「aaa」で議論になっていない

### 各レビュアーの評価

ディベート初心者: 何を書けばいいか分からない。
経験者: 制約がなさすぎて論点がない。
UX: ヒントはプレースホルダで足りる。長文ルールは読まれない。

### 最大の問題

議論の始め方が分からない。

### 議論

賛成: 最低文字数で短文を止める。
反対: 硬い制限は萎縮する。
最終判断: 生徒は 8 文字未満を送らせず理由を促す。議長は対象外。

### 実施した改善

* 空状態に 3 手順
* 理由付きプレースホルダ
* 8 文字ガイド
* テーマ下に「賛成か反対かを選んで理由を書く」

### 再テスト

結果: コードと空状態 JSX を確認。既存テストルームは短文が残る。

### 改善前 / 改善後

改善前: 「発言…」。改善後: 「賛成の理由を書く（例: …）」。

### 新しい問題

* 既存の短文は消えない（過去ログ）

### 次回確認

* 新規ルームで最初の投稿が 8 文字未満で止まるか

## Iteration 4

### 今回のテスト

通報ボタンの可視性、ニックネーム画面、本人確認ダイアログ。

### 発見した問題

1. 通報が muted で、自分の投稿ばかりの画面では存在に気づかない
2. ニックネームに本名を入れられる
3. 学籍番号を知っていれば他人の本名確認ダイアログまで進める

### 各レビュアーの評価

コミュニティ: 匿名性は UI 上あるが、認証は知識ベース。通報は管理者のみで議長には届かない（仕様）。
初心者: 「タロ」は匿名に見える。

### 最大の問題

荒らし短文と、ニックネームへの本名混入。

### 議論

ブロック機能は今は作らない（議長の強制退出がある）。通報の視認性だけ上げる。

### 実施した改善

* 通報をローズ色に
* ニックネーム画面に「本名や学籍番号は使わない」

### 再テスト

結果: 文言と色を確認。なりすまし耐性は学籍番号フローの限界として残る。

### 新しい問題

なし（認証方式は次サイクル）。

### 次回確認

* 他人の発言がある部屋で通報モーダルが開けるか

---

## Iteration 5

### 今回のテスト

スマホ幅（390）でチャット操作。管理画面の共有手段をコード確認。

### 発見した問題

1. 立場ボタン＋2行入力＋Ctrl+Enter で本文が狭い
2. ニックネームがヘッダーで消えていた（`hidden sm:inline`）
3. 議長が UUID を手共有する前提

### 各レビュアーの評価

スマホUX: タブ切替は良い。入力帯が厚い。
ゲーム: 勝敗がなくリプレイは授業進行依存。

### 最大の問題

教室配布が UUID 手打ちになっている。

### 議論

個別トークンURL（候補1）は転送で破られる。今はルーム共通の招待リンク1本が運用と精度のバランスが良い。

### 実施した改善

* 管理画面に招待リンクのコピー
* Ctrl+Enter 案内を `sm` 以上に限定
* ヘッダーにニックネームを常時表示（モバイルは truncate）

### 再テスト

結果: 管理 UI はコード確認。スマホ入力帯はヒント非表示で薄くなる。

### 新しい問題

* 本番未デプロイのためスマホ実機の再確認が残る

### 次回確認

* デプロイ後に招待リンクを貼って入室できるか
